# 跨平台本地 ASR 提词器调研计划

## 1. 调研目标

为 Windows、macOS、iOS、iPadOS 和 Android 提词器建立可验证的本地语音识别选型依据。最终不是选出一个覆盖所有设备的模型，而是形成：

1. 系统离线识别与自带模型共存的统一引擎接口。
2. 按设备能力自动选择模型的分档策略。
3. 对“正常跟读、读错纠正、短距离重读、跨页重读”的端到端评价体系。
4. 可重复执行的设备基准、语料和结果表。
5. 模型权重、训练数据和再分发权限的许可证清单。

### 核心研究问题

- 哪类流式 ASR 在手机端能同时满足中文准确率、低延迟、内存和温升限制？
- 系统离线识别在哪些平台、语言和设备上可以可靠使用？
- ASR 的字符错误率与最终稿件定位效果有多强的相关性？
- 对已读内容进行重读时，多长上下文才能可靠触发自动回退？
- 是否需要为低、中、高端设备提供不同模型，或提供“省电/标准/高精度”模式？

## 2. 范围与边界

### 纳入范围

- 普通话为第一优先级，中英混读为第二优先级。
- 全程本地处理，运行时禁止上传音频和转写文本。
- 系统级离线识别与应用内 ASR 模型。
- 流式或可模拟流式输出的 ASR。
- 正常前进、读错继续、自我纠正、向前跳读、短距离重读、跨页重读。
- 手机、平板和桌面设备的 CPU、内存、功耗、温升和包体影响。

### 暂不纳入

- 云端 ASR 和混合云回退。
- 多人会议转写、说话人分离和录音后精确字幕。
- 使用 LLM 直接判断稿件位置。
- 第一阶段的方言全覆盖。方言在普通话方案稳定后单独立项。

## 3. 总体技术假设

```text
AudioSource
  -> SpeechEngine Adapter
       -> Apple On-device Speech
       -> Android On-device Speech
       -> Windows Installed Speech Runtime
       -> sherpa-onnx Local Model
       -> Experimental Engine
  -> Incremental Transcript Events
  -> Chinese Normalizer
  -> Bidirectional Script Tracker
  -> Page State Machine
  -> Highlight / Scroll / Page Turn
```

必须让识别引擎与稿件跟踪器解耦。所有引擎输出统一事件：

| 字段 | 用途 |
| --- | --- |
| `utterance_id` | 区分当前语句及重启后的结果 |
| `text` | 当前增量转写 |
| `is_final` | 临时结果或稳定结果 |
| `confidence` | 引擎提供时记录，不强制假造 |
| `audio_start_ms` / `audio_end_ms` | 计算识别延迟 |
| `emitted_at_ms` | 计算首结果和稳定结果延迟 |
| `engine_id` / `model_id` | 可复现实验条件 |

## 4. 候选方案池

候选池只表示进入调研，不代表已选型。每个模型必须记录精确版本、下载地址、文件哈希、量化方式、模型总大小和许可证。

### A. 系统离线识别基线

| 平台 | 接口 | 调研重点 |
| --- | --- | --- |
| macOS/iOS/iPadOS | `SFSpeechRecognizer` | `supportsOnDeviceRecognition`、强制 `requiresOnDeviceRecognition`、中文增量结果稳定性、任务时长限制 |
| Android | `createOnDeviceSpeechRecognizer` | 厂商差异、已安装语言、连续识别重启、后台/前台限制、是否真正端侧 |
| Windows | `Windows.Media.SpeechRecognition` | MSIX 身份、已安装语言包、连续会话、中文支持和结果粒度 |

硬规则：能力检查失败时显示“系统离线识别不可用”，不得静默切换到联网服务。

### B. 统一跨平台主候选：sherpa-onnx

首轮测试以下模型族：

- 中文或中英双语 Streaming Zipformer，优先 INT8 和 small 变体。
- Streaming Paraformer bilingual zh-en，测试 FP32 与 INT8。
- 轻量中文 Zipformer 14M，作为低端设备候选。
- WenetSpeech Streaming Zipformer，作为普通话质量候选。
- 必要时加入 SenseVoice/Paraformer 非流式模型，配合 VAD 做短块识别，只作为对照组。

选择原因：sherpa-onnx 官方支持 Windows、macOS、iOS、Android、Dart/Flutter、流式 ASR 和本地运行，便于保持相同推理栈。

### C. 对照候选

- **whisper.cpp tiny/base 量化模型**：跨平台成熟，作为准确率和多语言对照；重点验证分块延迟、结果修订和手机温升，不默认认为适合实时翻页控制环。
- **FunASR Streaming Paraformer**：作为中文流式准确率参考，并评估导出 ONNX 后接入统一运行时的成本。
- **WeNet runtime**：作为流式中文和上下文偏置参考。如果 sherpa-onnx 已能承载相同模型，避免维护第二套运行时。

### D. 暂缓候选

- 仅支持英语或中文效果无依据的模型。
- 需要持续联网下载运行组件的方案。
- 权重没有明确再分发/商业使用许可的模型。
- 只能整段录音后输出、无法在可接受延迟内模拟流式的模型。

## 5. 设备分档

不能只在开发者旗舰机上测试。正式结论至少覆盖以下档位：

| 档位 | 移动设备目标 | 桌面设备目标 | 预期策略 |
| --- | --- | --- | --- |
| L0 系统基线 | 支持对应系统端侧识别的设备 | 支持系统离线语言包的设备 | 不下载应用模型 |
| L1 低资源 | 4 GB RAM、较旧中端 SoC | 8 GB RAM、老款 x64/Apple Silicon | INT8 小模型、1 线程或低线程数 |
| L2 主流 | 6-8 GB RAM、近年中高端 SoC | 16 GB RAM 主流设备 | INT8 标准模型 |
| L3 高性能 | 8 GB 以上旗舰 SoC/平板 | Apple Silicon 或现代 x64 | 高质量模型或双阶段解码 |

每个平台至少准备一台接近最低支持线的真实设备。模拟器不能用于性能、功耗和温升结论。

## 6. 测试语料设计

### 6.1 两阶段语料

**快速筛选集**

- 6 名说话人，男女声和不同语速均衡。
- 每人约 12 分钟，总计约 72 分钟。
- 用于淘汰明显不满足实时性或准确性的候选。

**正式验证集**

- 至少 20 名说话人，每人约 15 分钟，总计不少于 5 小时。
- 不同年龄、口音、语速和麦克风距离。
- 测试人不能全部来自开发团队。

### 6.2 场景组成

| 场景 | 目的 |
| --- | --- |
| 正常逐字朗读 | 基线跟踪和翻页 |
| 漏读 1-5 字后继续 | 检验局部容错 |
| 读错一个词后继续 | 检验 ASR/匹配器容错 |
| 读错后立即重念当前句 | 检验小范围回退与防振荡 |
| 回退 1-2 句重读 | 检验短距离自动跳回 |
| 回退到上一页重读 | 检验向后翻页 |
| 跳过一段继续读 | 检验向前重定位 |
| 插入 3-10 秒脱稿内容 | 检验丢失与恢复 |
| 多处存在相同短句 | 检验歧义和误跳 |
| 数字、英文缩写、专有名词 | 检验归一化和上下文偏置 |
| 安静/中等噪声/远场 | 检验真实使用环境 |

### 6.3 标注格式

每段录音保留：

- 原始稿件及分页边界。
- 实际朗读文本。
- 音频时间轴上的目标字符位置。
- `forward`、`self_correct`、`rewind`、`skip`、`ad_lib` 事件。
- 每次预期翻页或回退的目标页码和目标字符。

需要同时保留固定音频回放测试和真人实时测试。固定音频保证模型间可重复比较；真人测试验证麦克风采集、回声消除和交互反馈造成的真实影响。

## 7. 评价指标

### 7.1 ASR 层

- 中文 CER；中英混读另外报告英文 WER。
- 首个非空增量结果延迟。
- 稳定文本延迟。
- Partial result 更新间隔 P50/P95。
- 已输出文本修订率和最大回滚长度。
- 实时因子 RTF。
- 丢失语句、幻觉和重复输出次数。

### 7.2 稿件跟踪与翻页层

这些指标优先级高于单纯 CER：

- 当前字符位置绝对误差 P50/P95。
- 当前页准确率。
- 正常向前翻页成功率与 P95 延迟。
- 当前句自我纠正的保持/回退正确率。
- 短距离重读跳回成功率与 P95 延迟。
- 跨页重读跳回成功率与 P95 延迟。
- 错误向前跳、错误向后跳次数/10 分钟。
- 位置振荡次数/10 分钟。
- 脱稿后恢复成功率和恢复时间。
- 人工干预次数/10 分钟。

### 7.3 资源与工程层

- 模型下载大小和安装后大小。
- 冷启动、模型加载和首轮推理时间。
- 空闲/识别峰值/20 分钟稳态内存。
- CPU、GPU/NPU 利用率；线程数。
- 20 分钟和 45 分钟连续运行的耗电、机身温升与降频。
- App 前后台切换、来电/音频中断后的恢复。
- 五个平台构建、签名、打包和升级模型的维护成本。

## 8. 初始验收门槛

以下是产品目标，不是现有模型的已确认成绩。经过首轮数据后可以调整，但调整必须记录原因。

| 指标 | 目标 | 硬淘汰线 |
| --- | --- | --- |
| 首个增量结果 P95 | `<= 500 ms` | `> 1000 ms` |
| 稳定位置延迟 P95 | `<= 900 ms` | `> 1500 ms` |
| 正常翻页成功率 | `>= 99%` | `< 97%` |
| 短距离重读跳回成功率 | `>= 97%` | `< 92%` |
| 跨页重读跳回成功率 | `>= 95%` | `< 90%` |
| 错误翻页/回退 | `< 0.2 次/10 分钟` | `> 1 次/10 分钟` |
| 20 分钟连续识别 | 无崩溃、无明显降频 | 无法实时运行 |
| L1 移动端峰值额外内存 | `< 500 MB` | `> 800 MB` |

CER 不设单独硬淘汰线。若 CER 较高但稿件定位指标达标，模型仍可保留；反之亦然。

## 9. 实验设计

### Phase 0：事实和许可证盘点，2-3 天

1. 固定系统最低版本和目标架构。
2. 建立候选模型清单，记录参数量、量化、文件大小、语言和推理模式。
3. 分别确认框架许可证、模型权重许可证、训练数据约束和再分发权限。
4. 对无法确认商业使用或再分发的权重标记为 `BLOCKED`，不进入产品候选。

交付物：`candidate_inventory.csv`、`license_matrix.md`、来源链接和哈希清单。

### Phase 1：桌面快速筛选，3-5 天

1. 使用同一批固定 WAV 测试系统引擎、sherpa-onnx 候选和对照模型。
2. 记录 CER、增量延迟、RTF、内存及结果修订行为。
3. 淘汰无法实时、无增量结果或许可不清晰的候选。
4. 每个资源档保留最多 2-3 个候选，防止移动端组合爆炸。

交付物：原始 JSONL 事件、资源 CSV、筛选报告。

### Phase 2：稿件跟踪器离线回放，4-6 天

1. 将每个 ASR 的完整增量事件流输入同一版本稿件跟踪器。
2. 比较字符匹配、拼音辅助、窗口大小、回退惩罚和确认帧数。
3. 专门测试重复句、读错重念和跨页重读。
4. 固定一套默认参数，并为保守/标准/灵敏模式定义差异。

交付物：跟踪指标表、错误案例库、参数选择说明。

### Phase 3：移动端真实设备基准，5-7 天

1. 在 L1/L2/L3 设备运行入围模型。
2. 先做固定音频注入，再做真人实时朗读。
3. 连续运行 20 分钟；决赛候选再运行 45 分钟。
4. 测量耗电、温升、内存、音频中断和应用生命周期恢复。

交付物：逐设备报告、热稳定性曲线、设备分档推荐。

### Phase 4：系统识别 A/B，3-4 天

1. 同设备比较系统离线识别与应用内模型。
2. 检查系统能力探测和禁止云端回退是否可靠。
3. 验证系统更新、语言包缺失和厂商差异。
4. 决定各平台默认值以及何时建议下载本地模型。

交付物：平台策略矩阵和故障回退设计。

### Phase 5：盲测和最终决策，3-5 天

1. 使用此前未参与调参的说话人和稿件。
2. 对候选引擎隐藏名称，进行端到端盲测。
3. 统计验收门槛、失败分布和置信区间。
4. 输出 ADR，确定默认模型、低资源模型和系统引擎策略。

交付物：最终报告、ADR、发布风险与后续优化列表。

## 10. 决策规则

### 推荐产品策略

- **系统离线识别可用且通过设备实测**：允许作为零下载选项，但不自动假设其优于自带模型。
- **L1 设备**：默认小型 INT8 流式模型，优先稳定延迟和温升。
- **L2 设备**：默认标准 INT8 中文/中英流式模型。
- **L3/桌面设备**：可提供高精度模型，但必须保持增量结果满足控制环延迟。
- **模型下载**：按需下载并校验哈希，不把所有模型塞进初始安装包。
- **自动选择**：依据 OS、CPU 架构、可用内存和一次短基准确定，用户始终可以覆盖选择。

### 评分方式

先执行硬淘汰，再对剩余候选评分：

| 类别 | 权重 |
| --- | ---: |
| 稿件定位、翻页和重读跳回 | 40% |
| 增量延迟和稳定性 | 20% |
| ASR 准确率 | 15% |
| 内存、耗电和温升 | 15% |
| 跨平台维护和包体 | 5% |
| 许可证与模型供应风险 | 5% |

许可证不明确属于硬阻断，不能靠评分抵消。

## 11. 关键风险

- **系统 API 不保证所有设备离线可用**：必须逐设备能力探测，禁止静默联网。
- **公开 CER 不可直接比较**：数据集、解码配置和量化不同，最终只采信统一测试结果。
- **模型许可证与框架许可证不同**：sherpa-onnx 源码许可证不能自动覆盖每个权重。
- **ASR 高准确率不等于好跟踪**：大模型可能因分块延迟和反复改写临时文本而降低翻页体验。
- **重复文本导致错误回退**：必须构造重复句压力测试，并报告歧义情况下保持当前位置的能力。
- **旗舰机结论无法外推**：移动端必须覆盖最低支持档和持续运行温升。
- **音频注入结果过于理想**：固定回放和真人朗读缺一不可。

## 12. 第一轮建议候选数量

为控制成本，Phase 1 最多测试：

- 3 个 sherpa-onnx 流式模型配置。
- 1 个 whisper.cpp 量化对照。
- 1 个 FunASR/WeNet 中文参考配置。
- 每个平台 1 个系统离线识别基线。

首轮后每个设备档最多保留两个本地模型进入真机测试。

## 14. 调研完成定义

只有同时满足以下条件，调研才算完成：

- 五个平台的系统离线识别能力与限制已经实测或明确标记无测试设备。
- 至少三个资源档位有真实设备数据。
- 所有最终候选都通过统一音频和盲测语料。
- 正常翻页、读错重念、短距离重读、跨页重读都有独立指标。
- 结果包含原始增量识别事件，能够重新运行稿件跟踪器。
- 模型权重许可证和再分发权限已留档。
- 最终 ADR 明确默认引擎、备用引擎、设备分档和失败回退行为。
